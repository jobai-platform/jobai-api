## 1. Context & Goals

AI Analysis is the core value proposition of the JobAI platform. Given a `CandidateProfile` and a `JobPosting`, the system computes a structured `MatchScore` (0.0–1.0) across 4 dimensions (skills, experience, location, salary) with a qualitative explanation in natural language.

**Non-functional requirements:**
- 100% on-premise inference (Ollama) → conformité nLPD / RGPD by design
- No PII ever sent to external services
- Hybrid cache: return instantly if analysis exists, launch async job otherwise
- Prod-ready from day one: stateful DAG, model routing, full observability

---

## 2. Architecture Overview

Four layers compose the AI system, integrated into the existing hexagonal architecture:

```
┌─────────────────────────────────────────────────────────────┐
│                    AGENTIC LAYER                            │
│   LangGraph DAG (stateful, 5 nodes, retry logic)           │
│   profile_extractor → job_extractor → semantic_retriever   │
│                     → scorer → reporter                     │
└───────────────────────────┬─────────────────────────────────┘
                            │ tools via MCP protocol
┌───────────────────────────▼─────────────────────────────────┐
│                     MCP LAYER                               │
│   3 MCP servers (separate processes, stdio)                 │
│   profile_server (8001) | jobs_server (8002) | vector (8003)│
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                   MEMORY LAYER (CAG)                        │
│   TimescaleDB + pgvectorscale (HNSW ANN index)             │
│   Embeddings pre-computed at profile/job upsert            │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│               OBSERVABILITY LAYER                           │
│   Langfuse self-hosted — full DAG tracing, token costs     │
└─────────────────────────────────────────────────────────────┘
```

## 3. Technology Decisions

| Concern | Choice | Rationale |
|---|---|---|
| LLM inference | Ollama (local) | Zero cost, zero data exfiltration, nLPD/RGPD compliant |
| Primary models | Mistral:7b, mistral-nemo:12b, mistral:22b | EU-origin (Mistral AI, Lausanne), open source |
| Embedding model | nomic-embed-text (Ollama) | 100% local, excellent quality/speed ratio |
| Vector store | TimescaleDB + pgvectorscale | Zero new infra (extends existing Postgres), HNSW ANN index, pgvectorscale activé dès le début pour ne pas migrer l'index plus tard |
| Orchestration | LangGraph | Stateful DAG, conditional retry, prod-ready from day one |
| MCP servers | Separate processes (stdio) | Better isolation, performance, maintainability |
| Observability | Langfuse self-hosted | LLM-native tracing, DAG visualization, cost tracking, RGPD compliant |
| Async execution | FastAPI BackgroundTasks | Zero extra infra for MVP, swappable to Celery via adapter pattern |

### Value Objects

```python
@dataclass(frozen=True, slots=True)
class MatchScore:
    overall: float           # 0.0 → 1.0 (weighted average)
    skills_score: float      # 0.0 → 1.0
    experience_score: float  # 0.0 → 1.0
    location_score: float    # 0.0 → 1.0
    salary_score: float      # 0.0 → 1.0
    explanation: str         # Natural language, generated by Mistral

    def __post_init__(self):
        for field in [self.overall, self.skills_score, ...]:
            if not 0.0 <= field <= 1.0:
                raise ValueError(f"Score must be between 0.0 and 1.0")
```

### Enums

```python
class AnalysisStatus(Enum):
    PENDING    = "pending"
    PROCESSING = "processing"
    COMPLETED  = "completed"
    FAILED     = "failed"

class TaskType(Enum):
    EMBEDDING      = "embedding"
    EXTRACTION     = "extraction"
    CLASSIFICATION = "classification"
    SCORING        = "scoring"
    EXPLANATION    = "explanation"

class AnalysisQualityTier(Enum):
    FAST      = "fast"       # ~5s  — 7B models
    BALANCED  = "balanced"   # ~15s — 12B models (default)
    PRECISE   = "precise"    # ~45s — 22B models
```

### Domain Rules
- `MatchScore` raises `ValueError` for any score outside `[0.0, 1.0]`
- `AIAnalysis.complete()` valid only from `PROCESSING` status
- `AIAnalysis.fail()` valid from `PROCESSING` status only
- Domain layer has zero imports from LangChain, SQLAlchemy, FastAPI, or Pydantic

## 5. Application Layer — `app/application/ai_analysis/`

### Ports (Abstract Interfaces)

```python
class AIAnalysisPipelinePort(ABC):
    @abstractmethod
    async def run(
        self,
        candidate_id: UUID,
        job_posting_id: UUID,
        tier: AnalysisQualityTier,
        analysis_id: UUID,
    ) -> MatchScore: ...

class EmbeddingPort(ABC):
    @abstractmethod
    async def embed(self, text: str, task: TaskType) -> list[float]: ...

class VectorStorePort(ABC):
    @abstractmethod
    async def upsert(self, id: UUID, vector: list[float], metadata: dict) -> None: ...

    @abstractmethod
    async def search(
        self, vector: list[float], top_k: int, filters: dict | None = None
    ) -> list[SimilarityResult]: ...

class LLMGatewayPort(ABC):
    @abstractmethod
    def get_model(self, task: TaskType, tier: AnalysisQualityTier) -> LLMConfig: ...

    @abstractmethod
    async def invoke(self, config: LLMConfig, prompt: str) -> str: ...

class AIAnalysisRepository(ABC):
    @abstractmethod
    async def save(self, analysis: AIAnalysis) -> None: ...

    @abstractmethod
    async def find_by_id(self, id: UUID) -> AIAnalysis | None: ...

    @abstractmethod
    async def find_by_candidate_and_job(
        self, candidate_id: UUID, job_posting_id: UUID
    ) -> AIAnalysis | None: ...

    @abstractmethod
    async def find_by_candidate(
        self, candidate_id: UUID, limit: int = 20
    ) -> list[AIAnalysis]: ...
```

### Use Cases

**`ComputeMatchScoreUseCase`** — Hybrid cache pattern (Option C)
1. Check if completed analysis exists for (candidate_id, job_posting_id) → return immediately (200)
2. If pending/processing → return current status (202)
3. If failed → reset existing record to PENDING (UPDATE, not INSERT — respects UNIQUE constraint), launch background task (202)
4. If none → create `AIAnalysis(PENDING)`, persist, launch background task (202)
5. Quality tier resolved from `CandidateProfile.preferred_quality_tier` (fetched inside use case via `CandidateProfileRepository`)
6. Return `Location` header pointing to analysis endpoint for polling

**`GetAnalysisUseCase`** — Polling
- `find_by_id` → return status + score if COMPLETED

**`IndexCandidateProfileUseCase`** — Triggered on every profile update
- Generate CV + skills embedding via `EmbeddingPort`
- Upsert into `VectorStorePort` with metadata

**`IndexJobPostingUseCase`** — Triggered on every new scraped job
- Generate job description embedding
- Upsert into `VectorStorePort`

**`GetCandidateJobMatchesUseCase`** — Top-K RAG search
- Embed candidate profile
- `VectorStorePort.search(top_k=20)` → ranked job list

## 6. Infrastructure Layer — `app/infrastructure/ai/`

### LangGraph DAG — 5 Nodes

```
START
  │
  ▼
[Node 1: profile_extractor]
  Tool: Profile MCP → get_profile, get_cv_text
  Model: TaskType.EXTRACTION (mistral:7b / mistral-nemo per tier)
  Output: structured_profile: dict (skills[], experience_years, salary_range, locations)
  │
  ▼
[Node 2: job_extractor]
  Tool: Jobs MCP → get_job_posting
  Model: TaskType.EXTRACTION
  Output: structured_job: dict (required_skills[], seniority, salary_range, location)
  │
  ▼
[Node 3: semantic_retriever]   ← Agentic RAG
  Tool: VectorStore MCP → embed_text, similarity_search
  Logic: embed profile → search top-K similar jobs for context
         if confidence < 0.6 → reformulate query + retry (max 3 rounds)
  Output: context_jobs: list[dict]
  │
  ▼
[Node 4: scorer]
  Model: TaskType.SCORING (routed by tier)
  Input: structured_profile + structured_job + context_jobs
  Output: raw_scores: dict {skills, experience, location, salary}
  │
  ▼
[Node 5: reporter]
  Model: TaskType.EXPLANATION (routed by tier)
  Input: raw_scores + structured_profile + structured_job
  Output: MatchScore VO (scores + explanation text)
  Persists: AIAnalysis(COMPLETED) via AIAnalysisRepository
  │
  ▼
END
```

## 9. Observability, Security & Compliance

### Langfuse Tracing
- Every LangGraph run generates 1 Langfuse trace with full DAG
- Each node = 1 span: inputs, outputs, model used, tokens, latency
- PII sanitization middleware strips email/phone before trace export
- Token cost per analysis stored in `ai_analyses.tokens_consumed`

### Rate Limiting
- `slowapi`: max 10 analyses/hour/candidate
- Applied at presentation layer (FastAPI middleware)

### MCP Server Auth
- Internal JWT token (signed, short-lived) required for all MCP server calls
- MCP servers never exposed to public API

### RGPD / nLPD Compliance
- All inference 100% on-premise (Ollama + TimescaleDB + Langfuse self-hosted)
- Zero PII sent to external services at any point in the pipeline
- Candidate can request deletion → cascade delete embeddings + analyses

### Structured Logging
- `structlog` throughout with `request_id` → `analysis_id` correlation
- Log levels: INFO for lifecycle events, WARNING for low-confidence scores, ERROR for failures

### Cost Alerting (on-premise)
- `tokens_consumed` tracked per analysis
- Background job checks rolling 24h average
- Alert if average > configurable threshold (log warning + Langfuse annotation)
